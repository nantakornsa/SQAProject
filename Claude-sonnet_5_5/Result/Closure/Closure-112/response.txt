The test below reuses the triggering scenario from `testIssue1058`. It has not been compiled or run against either version.

In `TypeCheckTest`, `testTypes(String)` fails the test if the type checker reports any unexpected warning. On the buggy version, template-type inference leaks `CLASS` into the replacement map for `foo`'s own template `T`. Passing `a` (type `function(number):string`) to `foo` then produces a spurious type-mismatch warning. The fix filters the inferred map to only the keys belonging to the function being called. With the fix there is no warning, so the test passes.

The test needs to sit inside `TypeCheckTest`, which already provides `testTypes`, so I show it as a class extending `TypeCheckTestCase`. That base class lives in the same package and holds `testTypes` in this version of the project. If `testTypes` is defined directly in `TypeCheckTest` instead, the method can be pasted into that class unchanged.

```java
package com.google.javascript.jscomp;

public class TypeCheckTemplateRegressionTest extends TypeCheckTestCase {

  public void testIssue1058() throws Exception {
    testTypes(
        "/**\n" +
        "  * @constructor\n" +
        "  * @template CLASS\n" +
        "  */\n" +
        "var Class = function() {};\n" +
        "\n" +
        "/**\n" +
        "  * @param {function(CLASS):CLASS} a\n" +
        "  * @template T\n" +
        "  */\n" +
        "Class.prototype.foo = function(a) {\n" +
        "  return 'string';\n" +
        "};\n" +
        "\n" +
        "/** @param {number} a\n" +
        "  * @return {string} */\n" +
        "var a = function(a) { return '' };\n" +
        "\n" +
        "new Class().foo(a);");
  }
}
```
