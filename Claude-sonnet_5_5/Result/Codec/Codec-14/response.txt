The test below encodes "Bendzin" with the GENERIC name type, the APPROX rule type and `concat=true`. It expects `bndzn|bntsn|bnzn|vndzn`, the fixed output. I have not run it.

The buggy version uses one shared `lang.txt` for every name type. That produces the extra `|vntsn` entry quoted in the failure message. The fix loads a separate `<nameType>_lang.txt` per name type, so the extra entry disappears.

```java
package org.apache.commons.codec.language.bm;

import static org.junit.Assert.assertEquals;

import org.junit.Test;

/**
 * Regression test for CODEC-187: language rules must be loaded per name type.
 */
public class PhoneticEngineLangRegressionTest {

    @Test
    public void testGenericBendzinUsesGenericLangRules() {
        final PhoneticEngine engine = new PhoneticEngine(NameType.GENERIC, RuleType.APPROX, true);

        final String result = engine.encode("Bendzin");

        assertEquals("bndzn|bntsn|bnzn|vndzn", result);
    }
}
```
