I haven't compiled or run this. It reuses the triggering test from the bug report, so it should fail on the buggy version and pass on the fixed one. In the buggy version, `CoreOperationRelationalExpression` calls `containsMatch((Iterator) right, left)` when the right operand is an iterator. That call swaps the operands, so `$a + $b <= $c` is evaluated as the reverse comparison and returns `false`. The fix adds a `containsMatch(Object value, Iterator it)` overload that keeps the original operand order.

I assumed `assertXPathValue(JXPathContext, String, Object)` is inherited from `JXPathTestCase`, as the triggering test implies.
