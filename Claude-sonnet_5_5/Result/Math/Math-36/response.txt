The test below checks `BigFraction.doubleValue()` and `floatValue()` with a numerator and denominator too large for a `double` or `float`. I haven't compiled or run it against the buggy and fixed versions.

The fraction is (10^401 + 1) / (2 · 10^400), which is about 5. On the buggy version, both `BigInteger.doubleValue()` and `BigInteger.floatValue()` return infinity for these values, so the division gives NaN. The fix shifts both values right until they fit, so the result is about 5.

The class extends `TestCase` in JUnit 3 style. I used `junit.framework.Assert`, which works with either JUnit version.

```java
package org.apache.commons.math.fraction;

import java.math.BigInteger;

import junit.framework.TestCase;

public class BigFractionLargeValueRegressionTest extends TestCase {

    public void testFloatValueForLargeNumeratorAndDenominator() {
        final BigInteger pow400 = BigInteger.TEN.pow(400);
        final BigInteger pow401 = BigInteger.TEN.pow(401);
        final BigInteger two = new BigInteger("2");
        final BigFraction large = new BigFraction(pow401.add(BigInteger.ONE),
                                                  pow400.multiply(two));

        assertEquals(5.0, large.floatValue(), 1e-15);
    }

    public void testDoubleValueForLargeNumeratorAndDenominator() {
        final BigInteger pow400 = BigInteger.TEN.pow(400);
        final BigInteger pow401 = BigInteger.TEN.pow(401);
        final BigInteger two = new BigInteger("2");
        final BigFraction large = new BigFraction(pow401.add(BigInteger.ONE),
                                                  pow400.multiply(two));

        assertEquals(5.0, large.doubleValue(), 1e-15);
    }
}
```
