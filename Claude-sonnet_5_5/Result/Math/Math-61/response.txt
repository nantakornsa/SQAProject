The fix changes the exception thrown for a non-positive mean from `IllegalArgumentException` (created via `MathRuntimeException`) to `NotStrictlyPositiveException`. The test therefore passes `-1` and `0` to the constructor and expects `NotStrictlyPositiveException`.

On the buggy version, the constructor throws an `IllegalArgumentException` that is not a `NotStrictlyPositiveException`, so the catch block misses it and the test errors. On the fixed version the expected exception is caught and the test passes.

I am assuming the existing test class extends `TestCase` (JUnit 3), which matches the triggering test's use of `fail` and `assertEquals`. `NotStrictlyPositiveException` is in `org.apache.commons.math.exception`. I also check that a valid mean of 10.0 is returned unchanged by `getMean()`.

```java
package org.apache.commons.math.distribution;

import junit.framework.TestCase;

import org.apache.commons.math.exception.NotStrictlyPositiveException;

/**
 * Regression test for MATH-349: the Poisson distribution constructor must
 * throw NotStrictlyPositiveException for a non-positive mean.
 */
public class PoissonDistributionMeanRegressionTest extends TestCase {

    public void testMean() {
        PoissonDistribution dist;
        try {
            dist = new PoissonDistributionImpl(-1);
            fail("negative mean: NotStrictlyPositiveException expected");
        } catch (NotStrictlyPositiveException ex) {
            // Expected.
        }

        dist = new PoissonDistributionImpl(10.0);
        assertEquals(10.0, dist.getMean(), 0.0);
    }

    public void testZeroMean() {
        try {
            new PoissonDistributionImpl(0.0);
            fail("zero mean: NotStrictlyPositiveException expected");
        } catch (NotStrictlyPositiveException ex) {
            // Expected.
        }
    }
}
```
