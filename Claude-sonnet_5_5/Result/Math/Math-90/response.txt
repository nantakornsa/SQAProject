The buggy `addValue(Object)` has no cast to `Comparable`, so a non-comparable argument ends up in the `TreeMap`. In the buggy version the first call with an `Object` is fine, but once a value is present the second call throws `IllegalArgumentException` instead of `ClassCastException`. The fixed version casts `(Comparable<?>) v` first, so both calls throw `ClassCastException`.

The test calls `f.addValue(new Object())`, which compiles against the deprecated `addValue(Object)` overload. It expects `ClassCastException` at both points, so it fails on the buggy version and passes on the fixed one.

I haven't compiled or run this against either version.
